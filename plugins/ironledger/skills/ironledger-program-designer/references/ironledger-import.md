# IronLedger import contract

This is the contract between the program designer and IronLedger: the file the skill writes for a lifter to import, the exercise names both sides share, and the lifter's one-time setup. The writer and the pre-flight gate implement these rules exactly, and a departure fails pre-flight.

The rules were established against IronLedger `main` at `ab31f4f` (v1.9.0) by running the app's own parser and re-import code, as the next section describes. The writer's CSV output is checked against the current app by the IronLedger program file checker (`check_program_file`), a port of the app's parser verified against v1.10.1, and the setup steps in ON were re-read in the v1.10.1 source.

## How the rules were checked

The parser rules were verified on 2026-09-23 by running IronLedger's own import parser (v1.9.0) on test files, and the re-import rules by running the app's own re-import modules. A few rules were read in the app's source but not run, because the behaviour lives in a screen. File references such as `programImport.ts:188-199` are to the IronLedger app source at v1.9.0 (`ab31f4f`), which is not public. This skill writes CSV, which the same parser reads (IL-26), and every template's CSV passes `check_program_file`.

## IL. The import file

Column summary (the rules below govern):

| Column | Header, written exactly | Cell type | Write | Never |
|---|---|---|---|---|
| A | Week | number | `1`, `2`, `3` | `Week 1`, `2.5`, `0`, `Deload` |
| B | Day | text | `Day 1`, `Day 2`, restarting each week | `Day 1 - Squat`, `Upper A`, `Day ?` |
| C | Exercise | text | the exact library name | plurals, abbreviations, parentheticals |
| D | Sets | number | a whole number, 1 or more | `2-3`, `AMRAP`, blank |
| E | Reps | text | `5`, `8-12`, `5+`, `5, 3, 1` | `10 to 12`, en-dash ranges, date cells |
| F | Load | number, or text for a list | `127.5`, `0`, `95, 97.5, 100`, blank only under IL-11 | `75%`, `RPE 8`, `140kg`, `170-180`, words |
| G | RIR | text | `2`, `1-2`, `2, 2, 1` | blank, negative, date cells |
| H | Notes | text | the IL-14 convention | line breaks, double quotes |

In the CSV every cell is text; "number" means the cell holds only digits (and a decimal point).

- **IL-1** [POL] The import file is a UTF-8 CSV: one header row (IL-3), then one row per prescription, in columns A to H and nothing else
- **IL-2** [POL] Name the file `IronLedger Block <N>.csv`, where N is the lifter's block number counted from 1 and never reset. IronLedger names the program with the file name minus its last extension, trimmed (app/import.tsx:296), so the program is `IronLedger Block <N>`. Put no name, date or version in the file name: a revised block keeps exactly the same name (IL-20)

> Note: program names from the test: `Block 1.xlsx` gives `Block 1`; `Block 1.v2.xlsx` gives `Block 1.v2` (only the last extension goes); `Block 1 (1).xlsx` gives `Block 1 (1)`; `.xlsx` gives the generic `Imported Spreadsheet`, which re-import never matches by name (reimport.ts:30-40).

- **IL-3** [POL] Row 1 is the header, written exactly `Week | Day | Exercise | Sets | Reps | Load | RIR | Notes` in columns A to H, with no title rows, blank columns, RPE column or Rest column. The first seven headers are IronLedger's own template order, so the parse reports sourceType `ironledger_template`, and a file in this layout imported with zero diagnostics
- **IL-4** [POL] The parser's accepted header aliases, matched case-insensitively on the trimmed cell (programImport.ts:188-199), are: week `week, wk, week #, week number`; day `day, session, workout`; exercise `exercise, exercise name, movement, lift`; load `weight, load, kg, kgs, lb, lbs`; sets `sets, set`; reps `reps, rep, rep target, target reps`; rir `rir, reps in reserve`; rpe `rpe`; rest `rest, rest time, rest (s), rest sec, rest seconds`; notes `notes, note, comments, coach notes, cues`. A row counts as a header only if it holds an exercise alias, and with no header row the column order defaults to Exercise, Weight, Sets, Reps, RIR, Notes (programImport.ts:202-223). The writer never relies on an alias; the skill uses this list only to read a sheet it did not write
- **IL-5** [POL] Week is a numeric cell holding a whole number from 1 to the block's week count, on every row. Never write text such as `Week 1`: when Week is the first column each such row reads as a section header, and the file imports nothing ("No sessions found in the spreadsheet."). `Week 1` and `wk 2` do parse when Week is not the first column, but the writer uses integers regardless. A decimal (`2.5`), `0`, `2 - Deload` or `Deload` is an error and the row is skipped
- **IL-6** [POL] Day is a text cell reading exactly `Day <n>`, with n running from 1 to the days per week and restarting each week. Every week has the same number of days, and rows are sorted by Week, then Day, then exercise order. The label is only a grouping key: it is not saved (the imported day has no name), and IronLedger numbers days across the whole program in order of first appearance, so week 2's first day in a 2-day plan is dayNumber 3. `Day 1 - Squat`, `Day 1: Upper` and `Day ?` are errors (row skipped); `Upper A` or `Squat day` import but the label is lost, so the day's name goes in Notes (IL-14)
- **IL-7** [POL] Exercise is a text cell holding one library name spelt exactly as `assets/exercise-library.json` spells it, or a name from the approved alias table (LB-1, LB-9). Variations, top-set and back-off labels and cues go in Notes, never in the name (IL-18)
- **IL-8** [POL] Sets is a numeric cell holding a whole number of 1 or more. A range such as `2-3` imports the top number with a warning and appends ` · 2-3 sets` to Notes; `AMRAP`, `0`, `3.5` or a blank cell is an error and the row is skipped. AMRAP is written in Reps (IL-9)
- **IL-9** [POL] Reps is a text cell in one of four forms: a whole number (`5`), a range with an ASCII hyphen (`8-12`), an AMRAP minimum (`5+`), or a per-set list with one entry per set (`5, 3, 1`). An AMRAP set gets its own row with Sets 1, because a `+` anywhere in a row stops reps auto-writing for every set of that row (tickTargets.ts:44-46). Never write `10 to 12` or an en-dash range (`10–12`): tick-to-target writes the first number (10) as the logged reps, whereas an ASCII-hyphen range writes nothing. Never let Reps be a date or number-formatted cell: an `8-12` that a spreadsheet app turned into a date imports silently as the serial `46246`. A blank Reps cell is an error
- **IL-10** [POL] Load is absolute: the load itself in the lifter's profile unit (F-10), as a numeric cell (`127.5`), `0` for a bodyweight movement, or a text per-set list with one entry per set (`95, 97.5, 100`). Never a percentage, an RPE, a unit suffix, a load range or a word: `75%` and `RPE 8` import with no diagnostic and a tick then logs 75 or 8 as the load; a percent-formatted cell arrives as `0.75`; `140kg` logs 140 but is still text; `170-180` and words such as `Bar` log nothing. Write the percentage and its base in Notes instead, for example `85% TM`
- **IL-11** [D] {M13} Load is left blank only on a row whose load the lifter chooses under double progression (A-6): an accessory with no prescribed load. Each such row raises IronLedger's one tolerated warning ("No load given. Imported as your last."), and in the logger both the tick and TARGET autofill fall back to the lifter's last logged load for that exercise (app/workout/[id].tsx:674-686, 778-811; tickTargets.ts:48-70). Main-lift, supplemental, top-set and back-off rows always carry an absolute load

> Note: The target is zero IronLedger import diagnostics. IL-11's warning is the single declared exception, because the designer leaves accessory loads to the lifter (A-6) and a fixed number would be prefilled every week under TARGET, working against double progression. The strict alternative is an absolute starting load on every accessory, moved by re-issue (IL-20). This skill keeps the blank loads.

- **IL-12** [POL] RIR is a text cell on every row: a whole number from 0 (`2`), a range with an ASCII hyphen (`1-2`), or a per-set list with one entry per set (`2, 2, 1`). Never negative, never blank (a blank RIR with no RPE raises a warning), and never a date cell (a `1-2` turned into a date imports silently as `46054`). The file has no RPE column (A-5): the logger opens a movement in RPE mode only when its first row carries a prescribed RPE, so an RIR-only file keeps every movement in RIR (app/workout/[id].tsx:706-719, 1477). A numeric RIR, or each list entry, is auto-written on tick into an empty effort cell
- **IL-13** [POL] Never write a Rest column. The parser reads one into its preview (`90`, `90s`, `3 min` and `1:30` parse; `2-3 min` warns), but the saved exercise has no rest field (its keys were id, name, weight, sets, reps, rir, rpe, notes), so the value is dropped and the rest timer runs at the lifter's default, 90 s unless they changed it (store/index.ts:305-307). Rest goes in Notes (IL-14)
- **IL-14** [D] Notes is one line of plain text, stored verbatim and shown behind the info icon on the movement card, where the notes of consecutive same-name rows are joined (app/workout/[id].tsx:1478-1516). This is the single canonical list of Notes tokens: voice.md VO-1 and rulebook F-4 use these tokens, spelt and cased exactly as shown. Segments appear in this order, separated by ` · ` (space, middle dot, space, the separator the parser itself uses at programImport.ts:602-604): (1) the week marker on every row of that week, `Deload week` (IL-15) or `Optional this week` (IL-29); (2) on the first row of each day, `Day: <name>` (a name, or a match-relative day such as `Day: MD+2`), then `Warm-up: <block>` and `Then: <session>` (IL-28); (3) the row label, `AMRAP`, `AMRAP Last Set` (IL-30), `Top set <range>` (for example `Top set 175-185`, CT-PLM-20) or `Back Down`; (4) `Superset A1` and `Superset A2` on a pair's rows (the next pair B1, B2); (5) `Tempo 3-1-1` and `Full ROM`; (6) the rest, `Rest 90 s`, `Rest 2 min` or `Rest 3 min`, `Rest 3-5 min` (L-16 heavy triples, singles and top sets); (7) the load basis (`85% TM`, `85% of top set`); (8) the unit of timed or distance work, `Reps in seconds` or `Reps in metres` (IL-28); (9) the main-lift warm-up (IL-17); then (10) the cue (the L-13 AMRAP cue, or the double-progression instruction such as `Add load when you hit 12 on every set at RIR 2`). An A-8 reason (a choice made for an injury or a dislike) takes the cue's slot, replaces the cue and is never dropped. Leave out empty segments. VO-1 caps the whole cell (20 words or fewer, logistics first, at most one cue) and wins where the two conflict: the cue is dropped first, and a dropped item goes in the hand-over. No line breaks and no double quotes, because a CSV re-save splits the first into a new row and strips the second
- **IL-15** [POL] A deload week is marked only by `Deload week` as the first Notes segment on each of its rows, plus its loads and RIR (L-7). Import never sets the week's deload flag, and a `Week 4 - Deload` header row loses its name when the sheet has a Week column (in the test the week imported as plain "Week 2")
- **IL-16** [POL] Supersets and circuits are consecutive rows labelled in Notes (IL-14). Import builds one `Main` block per day (programImport.ts:446), and the logger starts the rest timer after every tick (app/workout/[id].tsx:744-751), so the lifter note tells the lifter to skip the timer inside a pair (ON-8)
- **IL-17** [D] Main-lift warm-ups (L-6) are written as one compact segment in the first work row's Notes, for example `Warm-up bar x20, 60x5, 75x5, 90x3`, and never as rows; in an L-7 deload week, which has no main-lift work rows, the warm-up goes on the day's first row as an IL-28 segment (`Warm-up: Squat bar x20, 45x5, 55x5, 65x3`); the full warm-up is in the hand-over. A warm-up row would need an RIR to pass the gate, a ticked warm-up counts as a set in IronLedger's set and tonnage totals (countedSets.ts:15-17), and a name such as `Squat (Warm-up)` becomes a custom exercise
- **IL-18** [POL] A top set and its back-offs repeat the plain library name on consecutive rows (`Squat` 1 × 3, then `Squat` 3 × 5), with the label in Notes. Never use a parenthetical such as `Squat (Top Set)` (LB-5). Consecutive same-name rows render as one movement card with continuous set numbers, and the card takes its effort mode from its first row, so every row of a card uses RIR (movementGrouping.ts:46-51; app/workout/[id].tsx:706-719)

> Note: A file that puts RPE 8 on a Squat top set and RIR 2 on the Squat back-offs opens the whole Squat card in RPE mode, and the back-offs' RIR targets never prefill. Don't write effort that way.

- **IL-19** [POL] Loads are written in the unit recorded in the profile, and one file never mixes units (F-10). The file carries no unit, and IronLedger never converts a program or a logged set when the lifter changes units; it converts only the bar and plates (store/index.ts:2314-2362; analytics/units.ts:6-23). The lifter confirms the unit before importing (ON-2)
- **IL-20** [POL] A revised block N is re-issued as the complete block (every week and every day, in the same layout) under exactly the same file name, with every week the lifter has already trained copied unchanged. IronLedger matches it to the saved program by fingerprint (SHA-256 over the sorted week|day|name|sets|reps|load|rir rows; notes and day labels are excluded) or else by name, ignoring case; archived programs are never matched (app/import.tsx:172-175). Update in place then replaces only the weeks after the highest week holding a logged session, keeps day ids by dayNumber and keeps any saved week the file omits (reimport.ts:43-66, 246-338; fingerprint.ts:24-42). In the test, a full re-issue matched by name, left weeks 1 and 2 untouched and updated weeks 3 and 4 with their day ids kept
- **IL-21** [POL] Re-issue traps, each reproduced by running the re-import code: a file holding only the untrained weeks restarted day numbers at 1 and left week 3 with six days (three new, three old); a renamed file (`Block 1 (1).xlsx`) with new loads matched nothing and would import as a new active program; a notes-only change matched by fingerprint and its preview diff read "weeks 1-4 identical", although the untrained weeks' notes did update. A change in day count or week order is a new block (N+1), never a revision
- **IL-22** [POL] A week holding any logged session is frozen, so a change to the current week has to be imported before the first session of that week. The re-import card defaults to Import as copy (app/import.tsx:162, 276), so the lifter must choose Update in place (ON-5); a copy is named `IronLedger Block <N> (v2)` (reimport.ts:357-373) and splits the block across two programs
- **IL-23** [POL] Block N+1 has a new file name, so it imports as a new program and becomes the active program immediately (app/import.tsx:489-490); block N stays in the library with its sessions. The next block is imported before the last session of the current block, because the program otherwise wraps to week 1 (ON-6)
- **IL-24** [POL] The pre-flight gate has two halves. (1) `designer.py preflight PROGRAM.json PROFILE.json --csv FILE` re-reads the written file and checks it row for row against the draft: week, day, name, sets, reps, load, RIR and notes. (2) `check_program_file` (the IronLedger MCP server, or `POST https://www.ironledger.app/api/tools/program-file`) with the whole file and its file name must return `imports` true, zero `error` and zero `match` issues, `skippedRowCount` 0, `newExerciseNames` equal to exactly the approved alias names the draft uses (LB-9), program name `IronLedger Block <N>`, and no warning other than IL-11's "No load given" on the rows the draft leaves blank. Any failure blocks the hand-over (G-7)

> Note: a name the lifter's phone already holds as a custom exercise would pass silently in the app (LB-4), so the gate counts on the checker, which holds no custom list. An exemplar file in this format imported with only its declared blank-load warnings.

- **IL-25** [POL] The gate's own checks, for what the parser accepts silently: every Load is a number, a number list with one entry per set, or blank under IL-11 (no `%`, letters or ranges); every Reps and RIR cell matches IL-9 or IL-12 (a spreadsheet re-save can turn `8-12` into `12-Aug`); every Exercise matches LB-1 character for character; the file has 8 columns; and the file name matches IL-2. Re-run the whole gate after any edit to the file
- **IL-26** [POL] Deliver a UTF-8 CSV, written by `designer.py build`, and check that same file (IL-24). No cell holds a double quote or a line break (IL-14): CSV drops doubled quotes (`"say ""brace"", then go"` imported as `say brace, then go`) and splits a quoted cell at a line break into a new row. Never open and re-save the file in a spreadsheet app: Excel, Numbers and Sheets can turn `8-12` or `1-2` into a date, and the file can't stop them. A UTF-8 byte-order mark is harmless
- **IL-28** [D] Warm-up blocks, mobility, sprints, runs and conditioning are not import rows. They go in the hand-over, and the day's first row carries a Notes segment such as `Warm-up: Limber 11` or `Then: 6 x 400 m` (IL-14). A day holding only such work has no import rows and takes no Day number (IL-6). Timed or distance strength work (carries, planks, neck isometrics) uses a library or alias name (LB-1, LB-9), with Reps in whole seconds or metres, the unit in Notes (`Reps in seconds` or `Reps in metres`), and a numeric RIR cap
- **IL-29** [D] A taper or meet week goes in its own block file (block N+1, IL-23). A rugby bye week keeps its rows, with `Optional this week` as the first Notes segment on each. Match-relative days go in Notes (`Day: MD+2`), because every week must have the same day count (IL-6)
- **IL-30** [D] Non-AMRAP percentage rows (5/3/1 work sets that aren't the AMRAP, FSL, BBB and back-downs) carry their RIR cap as a range the logger won't auto-write, default `3-5`, because a single number is auto-written on tick (IL-12) and would read as a logged effort. A rule that sets a different cap keeps it, still written as a range. The AMRAP row carries `1-2`. An accessory `AMRAP Last Set` is its own row (Sets 1, Reps such as `12+`, RIR `0-1`) and is excluded from A-6's double-progression check

## LB. Exercise names

- **LB-1** [POL] Emit only exercise names spelt exactly as in `assets/exercise-library.json`, the 202-entry extract (201 unique names; `Close Grip Bench Press` appears twice, at exerciseLibrary.ts:87 and :873) of `src/data/exerciseLibrary.ts` at ab31f4f. IronLedger's own check ignores case and punctuation (lowercase, then every run of non-alphanumerics becomes a space: matchExercise.ts:29-35, 75-86), so `squat`, `SQUAT` and `Pull-Up` were all known, but the designer requires the library's exact spelling so every file, record and alias keys on one string
- **LB-2** [POL] The fuzzy matcher (matchExercise.ts:9, 42-72, 94-120): an unknown name is split into normalised tokens, each singularised (a trailing `ies` becomes `y` on tokens over 4 letters, a trailing `s` is dropped on tokens over 3 letters, `ss` is kept), and scored by the Dice coefficient (2 × shared tokens ÷ total tokens) against every library and custom name. A score of 0.8 or more raises a `match` that blocks IMPORT until the lifter taps KEEP or USE (app/import.tsx:197-205, 535); a lower score silently creates a custom exercise. A score of 1.0 still blocks: `Leg Curls`, `Romanian Deadlifts`, `Lat Pulldowns`, `Cable Tricep Pushdowns`, `Face Pulls`, `Hip Thrusts`, `Walking Lunges` and the word swap `Incline Dumbbell Press` all raised a match
- **LB-3** [POL] Known false matches at 0.8, which corrupt the record if the lifter taps USE: `Hamstring Curl Machine` to Machine Curl (a biceps exercise), `Pause Bench Press` to Bench Press (the pause is lost), and `Weighted Pull Up` to Pull Up and `Weighted Chin-up` to Chin Up (the weighted variant merges into the bodyweight lift). Also blocking, though the suggestion is right: `Barbell Bench Press` to Bench Press, `Barbell Hip Thrust` to Hip Thrust, and `Tricep Pushdown` to Cable Tricep Pushdown
- **LB-4** [POL] A name scoring under 0.8 imports with no diagnostic as a custom exercise with category `other`, muscleGroups `[]`, equipment `[]` and isCompound false (app/import.tsx:426-442). Silent in the test: `Pull-Ups`, `Pull Ups`, `Pullups` and `Chin-Ups` (the token `ups` is too short to singularise), `RDL`, `OHP`, `DB Row`, `Seated Hamstring Curl`, `Adductor Machine`, `Cable Y-Raise`, `Tibialis Raise`, `Pause Deadlift`, and every parenthetical variant (`Squat (Top Set)`, `Squat (Warm-up)`, `Bench Press (Back-off)`). A created name joins the lifter's custom list and later imports accept it silently (with `Pull-Ups` and `RDL` in the custom list, neither was reported), so pre-flight always runs with an empty custom list (IL-24)
- **LB-5** [POL] Analytics, records and IronLedger's weekly lift keys strip every parenthetical and lowercase the rest (computeLiftRecords.ts:8-12; movementGrouping.ts:46-51): in the test a `Squat (Top Set)` set joined the `squat` key. A parenthetical variant therefore counts as the base lift in the app's numbers while still being a custom exercise with no muscle groups, so the designer never emits one. The library's only parenthetical name, `Dumbbell Pullover (Back Focus)` (exerciseLibrary.ts:426), shares its key with `Dumbbell Pullover`
- **LB-6** [D] One spelling per lift for the lifter's whole lineage. The library holds pairs IronLedger treats as different lifts, because their keys differ: `Squat` and `Back Squat`, `Deadlift` and `Conventional Deadlift`, `Overhead Press` and `Military Press`. Defaults: `Squat`, `Bench Press`, `Deadlift`, `Overhead Press`. Record any other choice in the profile and never switch mid-lineage, because records and trends key by name
- **LB-7** [D] {M12} Primary muscle: `muscleGroups[0]` is the primary group by convention, not a typed field (SwapSheet.tsx:61 reads it); for example `Close Grip Bench Press` is [triceps, chest] and `Bench Press` [chest, triceps, shoulders]. Weekly fractional sets count 1 for `muscleGroups[0]` and 0.5 for each other listed group, over counted sets only. Entries list 1 group (84 entries), 2 (74), 3 (41) or 4 (3), counted from the vendored library
- **LB-8** [POL] Vocabulary gaps: the 16 groups are chest, back, shoulders, biceps, triceps, forearms, quadriceps, hamstrings, glutes, calves, abs, obliques, lower_back, traps, lats and full_body (exerciseLibrary.ts:25-41). There are no delt heads: `Lateral Raise`, `Rear Delt Fly` and `Overhead Press` all count as `shoulders`, so side and rear delt volume needs the designer's own tag. There is no adductor group: `Hip Adduction Machine` (exerciseLibrary.ts:1320) and `Hip Abduction Machine` are both [glutes]. `back` overlaps `lats`, `traps` and `lower_back`, and Olympic lifts, carries and cardio are `full_body`
- **LB-9** [POL] A movement the library lacks (for example weighted dip, cable Y-raise, reverse hyper, tibialis raise or pause deadlift) is either substituted from the library or entered in the alias table with its muscle groups, once approved (A-9). An alias name must score under 0.8 against every library name, or it blocks import with a match, and the gate expects it in newExerciseNames (IL-24). A custom exercise in the export (`customExercises[]`, muscleGroups `[]`) is counted only through the alias table; an unmapped one is a data gap to raise with the lifter, never guessed

## ON. Setup and import

- **ON-1** [POL] The lifter gets the setup steps below with their first import file, and again after a new phone or a reinstall. IronLedger has no coach features, so the steps are the only instructions that travel with the file
- **ON-2** [POL] Before the first import the lifter checks that Settings, UNITS, Weight (KG or LB) matches the profile unit (IL-19). Settings opens from the Profile tab's Training row, or from SETTINGS on the Routine tab once a program is loaded
- **ON-3** [POL] Autofill source must be TARGET, so the logger prefills the file's numbers rather than the last session's. Path: Settings, WORKOUT LOG, Autofill source, TARGET (the options read LAST, BEST, TARGET); the row shows only while Autofill weight or Autofill reps is on. Under TARGET, rows with no load fall back to the last workout (IL-11)
- **ON-4** [POL] Effort: the logger picks RIR or RPE per exercise, per session, from the prescription (IL-12), and the lifter can change it under EFFORT INPUT in the exercise's ... menu. The steps tell the lifter to log RIR on every set and to switch any exercise that shows RPE back to RIR
- **ON-5** [POL] Import: save the file without renaming it, then LIBRARY (Routine tab), +, IMPORT INSTEAD, CHOOSE FILE; with no program loaded, Import under LOAD A PROGRAM on the Routine tab does the same. For a revised block the lifter picks Update in place, then UPDATE PROGRAM, because the card defaults to Import as copy. If Update in place is not offered, or IronLedger asks to confirm names, the lifter stops and asks the AI to check the file again (IL-21, IL-22, LB-2)
- **ON-6** [POL] The next block is drafted and imported before the last session of the current one, and importing it makes it the active program (IL-23). The steps tell the lifter to come back for the next block, rather than start again at week 1, if they reach the end first
- **ON-8** [POL] The steps also cover logging: tick a set only once it is done, type the actual numbers first if they differ from the plan, and read rest, supersets, tempo and warm-ups in each exercise's notes (the i button), skipping the rest timer inside a superset (IL-13, IL-14, IL-16)
- **ON-9** [POL] The steps are given as written below, changing only the unit in step 1 (KG or LB, from the profile) and the file name

```text
Setting up IronLedger for this program

Do these two things once, before you import anything.

1. Units. Open the Profile tab, tap Training, and under UNITS check that Weight is set to KG. The program is written in that unit, and the app does not convert it.
2. Autofill. On the same screen, under WORKOUT LOG, make sure Autofill weight is on, then set Autofill source to TARGET. The app then fills in the program's weights. Where the program leaves the weight for you to choose, it fills in what you lifted last time.

Importing the program

3. Save the file (for example "IronLedger Block 1.csv") to your phone without renaming it, and don't open and save it in a spreadsheet app first.
4. In IronLedger, tap LIBRARY on the Routine tab, then the + button, then IMPORT INSTEAD, then CHOOSE FILE, and pick the file. If you have no program loaded yet, you can tap Import under LOAD A PROGRAM on the Routine tab instead.
5. Some accessories may show "No load given". That is on purpose: you choose the weight for those. If the app asks you to confirm exercise names, stop and have the file checked again.
6. Tap IMPORT. The program becomes your active program straight away.

When a block is updated

7. Import it the same way. IronLedger recognises it and offers "Update in place" or "Import as copy". Choose Update in place, then tap UPDATE PROGRAM. The weeks you have already trained stay exactly as they were.
8. If you don't see "Update in place", stop. It usually means the file name changed when it was saved, for example to "IronLedger Block 1 (1).csv".

In your sessions

9. Effort is written as RIR, which means reps in reserve: how many more good reps you could have done. Log RIR on every set. If an exercise ever shows RPE instead, tap its ... menu and set EFFORT INPUT back to RIR.
```
